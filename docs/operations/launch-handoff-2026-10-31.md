## Product contract and limits

Both launch plans may use semantic evaluation; Pro provides the larger paid allowance. A completed semantic PASS or BLOCK costs one validation. Bad input and internal reasoning do not; internal failures release quota. Delivery failure keeps the charge for its completed verdict. Async content is held only for pending/retry work and erased at a terminal transition; abandoned jobs expire after one day. New decision logs contain metadata only; history cleanup uses seven days for Free and thirty for paid accounts. Backups, historical rows and provider retention still require operational verification.

Content is capped at 12,000 bytes, total body at 16,384, metadata at 2,048, and model output at 300 tokens. Input bytes bound model input size but are not a tokenizer-based token count. Global admission is 10,000 non-skipped reservations per 24 hours; async retries may make up to three model attempts, so this is **not a dollar-denominated spending cap**. Use provider project budgets/alerts and measured launch caps; verify whether provider budgets actually stop requests. These defaults need load/cost evaluation before wider sales.

Default mode is validate_only. Dispatch is opt-in and requires destination verification. BLOCK and SKIPPED never authorize execution. Async chat returns pending, not "message delivered". A transport acknowledgement is not downstream execution proof. Idempotency is scoped to the API key and original action; a duplicate returns 409 rather than blindly replaying it. Retain the original action and stable ID in the customer's own durable executor. Do not change keys or generate a new identity to retry an uncertain payment/action.

Callback support is HTTPS DNS hostnames on port 443, no credentials/query/fragment, IPv4 public addresses only. This deliberately rejects IPv6-only destinations at launch. The receiver example accepts into a durable outbox; its application worker still needs downstream idempotency.
